这是什么

DeepSeek Local 是一个跑在你自己电脑上的 DeepSeek 客户端：界面照着官方 App 做，但每一句话都由 你自己的 API Key 发出，对话记录只落在本机硬盘里。

它由四块组成：一个零依赖的 Node 服务（server.mjs，默认 8787 端口）、一套原生前端 （public/，无框架）、一个 C++ 原生启动器（托盘、单实例、内存裁剪），以及一个 Inno Setup 安装包。除了调用 DeepSeek 官方接口和（可选）本机 Ollama，其余全在本机闭环。

安装与第一次启动

双击 DeepSeekLocal-Setup-1.0.1.exe，中文向导，一路「下一步」即可。默认装到 %LOCALAPPDATA%\Programs\DeepSeekLocal，按当前用户安装，不需要管理员权限。

  • 装完会在桌面和开始菜单生成「DeepSeek Local」，指向 DeepSeekLauncher.exe。
  • 用户数据独立存放在 %LOCALAPPDATA%\DeepSeekLocal\data，升级/重装不会覆盖。
  • 卸载走系统「应用和功能」，会先结束正在运行的进程再删程序文件；不会删你的对话数据。
关于「错误 5 拒绝访问」：早前版本如果安装包是从受限目录（带 Low 完整性标签的位置）双击运行的， Windows 会拒绝它写程序目录和注册表。现在分发包已提升为 Medium 完整性标签并加了安装日志开关， 双击即可正常安装；万一失败，日志会自动写到 %TEMP%\Setup Log*.txt。

第一次打开要做的两件事

  • 左下角「设置」→ 填 DeepSeek API Key（只存本机 data/settings.json）。
  • 需要联网/深度思考时在输入框下面的胶囊里打开；默认模型选「自动（按内容路由）」最省心。

主界面

左侧是会话列表（按「今天 / 最近 7 天 / 最近 30 天 / 更早」分组，带相对时间），顶部是标题与上下文占用条 （顶部那根横条会随上下文预算变橙或变红），底部是输入区。整页在 900px 以下自动切成单栏。

输入区：一个输入框，装下全部开关

输入框是单层的：不再有「框里套一个筐」的观感，聚焦时是一圈柔和光晕而不是硬边框； 下面的胶囊从左到右是：附件、联网、深度思考、混合模式、思考强度、语音。

  • 联网：打开后模型可主动搜、可读链接；关掉就纯离线推理。
  • 深度思考：先想再答；旁边的「高 / 中 / 低」控制思考强度。
  • 混合模式（二分树图标）：先让 V4.1 Flash 出一份大纲，再让 V4 Pro 按大纲把正文写完。
  • 语音：输入语音转文字，回答也能朗读出来。
  • 附件：图片、文档、音频、视频都能直接丢进去；视频会自动抽关键帧并转写。

全家桶能力

按内容自动路由

模型选「自动」时，每条消息会先判意图：闲聊交给 V4 Pro，逻辑/计算/排错交给 V4.1 Flash（带思考）， 要写成篇的东西先 Flash 出大纲再用 Pro 润色。回答顶部会标出「自动路由 · 逻辑思考 · V4.1 Flash」。

按对话自动调提示词与温度

每一轮先看这段对话长什么样：是代码、数学、创作、事实问答还是短闲聊，是第几轮、累计多少 token、有没有附件。 然后临时改这一轮的 temperature（代码 0.35 / 数学 0.30 / 创作 +0.15 / 事实 0.55 / 短问 0.85，长对话再降 0.15）， 并追加一小段只作用于这一轮的系统提示。回答上方会标一个「自适应 · 温度 x」的角标， 不会改动你在设置里写的默认温度。

音视频两段式

发视频/音频时，先让快模型把转写与抽帧压成一份要点清单，再让 Pro 按要点回答——比一次性把长转写塞给大模型省一半以上 token，也更少跑题。

拖入压缩包，一键整理成对话

把文件拖进窗口，整个界面会浮起一层虚线提示卡，松手即开始整理。四种判定：

你拖进来的它会怎么处理
DeepSeek 导出包（含 chat_session_index.json）按官方结构还原每个会话（含思考过程、引用、图片），图片落到 data/media/imported-*/
任意含会话数组的 JSON 整包识别 conversations / messages 字段，逐个导入
普通资料压缩包按顶层目录分成 2–6 组，每组生成一个「资料包 · 目录名」会话，正文是文件清单 + 内容
单个 .md / .txt / .json当成一份材料，生成一个会话
限制（都是防止一次吞掉整台机器）：单包 ≤ 200 MB；只认文本类文件，最多 60 个、单文件取前 6000 字、 单个会话累计 4 万字；图片/文档/二进制不会硬塞给模型；压缩包里一个文本都没有时直接报错并说明原因。 同名会话再次导入会替换旧的，不会叠两份。

上下文与记忆

长对话不会被硬截断，而是分四层管：最近的热区原样发送；更早的消息压成结构化摘要（事实 / 决定与理由 / 偏好 / 未完成）； 历史片段建本地词面索引，按当前提问召回；再按半衰期做时间衰减，太久的内容只留一行关键词提示。 顶部「N% 记」就是上下文占用，点开能看到压缩记录，每条都能展开回原文（原文在 data/archive/）。

日历、时钟与 QQ 通道

「日历」整页是月视图 + 今天/未来 7 天清单，事件可以「在会话里问」一键丢进对话；开了「日程进上下文」， 模型每轮都知道你最近几天的安排。「时钟」是当前时间、今天还剩什么、接下来 7 天。 「QQ」走 OneBot 11 HTTP，连的是你自己的 NapCat；关 / 只发 / 收发三档，二维码过期会明说「这张码是几天前的」， 也能一键重启 NapCat 逼它出新码。

C++ 启动器与内存

桌面图标指向的不是 Electron 本体，而是一个 0.3 MB 的原生启动器：双开只会有一个实例；服务没起就替你 拉起（沙箱冲突时自动加 --no-sandbox 重试）；8787 被占用会自动顺延扫描端口； 托盘菜单有「打开应用 / 在浏览器打开 / 内存优化 / 退出」；退出时进程树一起收干净。

项目实测值
启动耗时（冷启到窗口可点）约 4–6 秒（含 Node 服务就绪）
常驻内存（4 个 Electron 进程合计）约 366 MB
「内存优化」后的工作集43.9 MB → 0.0 MB（页转入 standby，回前台即恢复）
私有提交（真实占用）290.4 MB → 290.4 MB（不变，如实标注）
自动优化节奏每 10 分钟一次，托盘可手动触发
安装包104.6 MB（locales 从 55 个精简到 3 个，省约 47 MB）
关于「内存优化」的诚实说明：SetProcessWorkingSetSize(-1,-1) 只是把工作集页挪到 standby， 不会减少私有提交。所以面板里两个数字都报，避免「一键省了 300 MB」这种假象。

沙盒验收：从安装到功能

为了排除「我这台机器上能跑」的偶然性，整套流程在一次性沙盒里重跑过一遍：静默安装到独立目录 → 全新数据目录 → 指向本地假上游（mock，不花真 token）→ 逐项断言。

已知限制

  • QQ 通道的真扫码登录还没端到端验过：需要先在你机器上启动 NapCat 并扫码，接口、二维码刷新、重启出码都已实现并单测过。
  • 联网搜索与读链接依赖 DeepSeek 官方工具与你的额度；关掉联网就是纯本地推理。
  • 本地压缩摘要默认优先用本机 Ollama，没装或失败会自动回落到 API。
  • Windows 10/11 x64；安装与运行都不需要管理员权限。
数据都在本机：data/conversations/*.json（会话）、data/archive/（压缩前原文）、 data/media/（图片与导入附件）、data/settings.json（Key 与偏好）。 想完全清空，退出应用后删掉 %LOCALAPPDATA%\DeepSeekLocal\data 即可。
