1这一份演示是怎么来的

演示不是“摆拍”：它跑在一个独立沙盒实例里——自己的数据目录、自己的端口、没有任何真实对话，也不读你的 API Key。

项目日常实例演示沙盒
数据目录data\demo-data\
端口87878899
对话你自己的真实记录三条示例会话（可重复生成）
API Key按需配置不配置（hasKey=False）
启动方式桌面快捷方式 / DeepSeek.exe双击 启动演示.cmd

怎么起、怎么停

  • 双击 启动演示.cmd：脚本先写一份 demo-data\settings.json（关掉“首启自动导入”，免得把真会话拷进演示），再起服务、等就绪、调 tools\seed-demo.mjs 灌演示数据，最后打开浏览器。
  • 想用窗口版：set DSAPP_DATA=…\demo-data、set PORT=8899，再起 dist\DeepSeek-win32-x64\DeepSeek.exe。
  • 停止：双击 停止演示.cmd（只结束 8899 上那个进程）。演示数据留着，下次接着用；想重来就删掉 demo-data\。
  • 重复跑 node tools\seed-demo.mjs http://127.0.0.1:8899 不会翻倍：它会先删掉上次灌的「演示 · …」再灌。

灌进去的三条会话，各有用途

  • 演示 · 一次问十件事 —— 一屏十个问题 + 一段 Python 代码块，用来看多问题排版、代码高亮、消息操作行。
  • 演示 · 长对话如何不丢上下文 —— 六段重复背景，用来演示分档压缩与“原文归档还能翻回来”。
  • 演示 · 拿来就能用的几件小事 —— 短问答，用来演示自动标题、预览、搜索结果。

2导入对话：先辨认，再落库

底栏第五个按钮「导入」是一个独立整页。文件拖进来先辨认，告诉你它属于哪一类、准备生成几个会话，再让你决定导不导——不是闷头灌数据。

你拖进来的它怎么处理
DeepSeek 官方导出包（含 chat_session_index.json）按官方结构还原每个会话（思考过程、引用、图片），图片落到 data/media/imported-*
任意含会话数组的 JSON 整包识别 conversations / messages 字段，逐个导入
普通资料压缩包按顶层目录分成 2–6 组，每组生成一个「资料包 · 目录名」会话，正文是文件清单 + 内容
单个 .md / .txt / .json当成一份材料，生成一个会话

限制：单包 ≤ 200 MB；文本类最多 60 个文件；单文件取前 6000 字；单会话累计 4 万字；图片/文档/二进制不会硬塞给模型。压缩包里一个文本都没有时，会直接说清原因（例如“这不是 zip（找不到 EOCD）”），不是静默失败。

和“拖进对话页”的区别：对话页拖文件 = 给这条消息加附件（图片 / PDF / Word / 文本 / 音视频）；只有导入页拖文件才是整理成对话。对话页拖进来一个 .zip，它会提示“像对话包，交给「导入」页整理”并跳过去，不会误当附件。

3摘要模型：本机没有就自动从国内镜像拉一个

长对话的压缩摘要优先交给本机 ollama 的小模型写——不走网络、不花 API 钱。问题是新机器上往往没装模型。现在这条路上加了自愈：

  1. 触发：要写摘要时发现本机 ollama 在线但没有可用对话模型，后台自动开始拉；也可以点设置里的「现在拉一个」手动触发。
  2. 先官方源：ollama pull qwen2.5:1.5b-instruct（不行退 qwen2.5:0.5b-instruct）。
  3. 再国内镜像：官方源拉不动，就依次换 魔搭 ModelScope（modelscope.cn/models/<repo>/resolve/master/<file>）与 hf-mirror.com 下 GGUF，存到 data/models/（先写 .part 再改名，按 2 MB 一步记进度）。
  4. 装进 ollama：生成 Modelfile（num_ctx 8192、temperature 0.3、Qwen ChatML 模板）后 ollama create，之后当普通模型用。
  5. 只用一次：同一个模型装过就复用；进度、来源、最近 20 行日志都能在 GET /api/context/model-pull 与设置页看到。

可调、可验

  • 环境变量 DSAPP_OLLAMA_CLI 指定 ollama 可执行文件；DSAPP_PULL_MIRRORS 换镜像（自测就是这么注入假镜像的）。
  • 自测脚本 node tools\model-pull-test.mjs：起假 ollama + 假镜像 + 假 CLI，验证「官方源失败 → 镜像下载 → ollama create → 可用」整条链路，13 项全过。
  • 全失败时的文案是 官方源和国内镜像都没拉成（检查网络或手动 ollama pull）；摘要照旧退回 API，不阻塞对话。

诚实的边界

  • 镜像那两条 URL 是公开的 HF / 魔搭路径，能用与否取决于当天的网络与仓库结构；拉不到会明确报错，不会假装成功。
  • 演示沙盒里没有 API Key，所以演示页只展示界面与本地能力，不发起真实联网/推理请求。
  • QQ 真扫码登录仍未端到端验证（需要你本机启动 NapCat 扫码）。
