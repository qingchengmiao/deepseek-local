# 两个 DSH 记忆插件里能搬给 DSL 的东西

调研对象：`dsh-neural-memory@1.1.0`、`dsh-mind@1.1.0`（tgz 已解到 `data/_pkgcheck/`，SHA256 与 release 一致）。
对照对象：`deepseek-app` 自己的记忆栈（`context.mjs`、`server.mjs` 的压缩/归档/检索、`user-learn.mjs`）。
日期：2026-11-25。

---

## 一、结论

**值得搬的，按性价比从高到低：**

1. **压缩便条的 prompt 结构**——零成本，改一段常量就能上。
2. **惊讶度写入闸门**——解决「同一件事被反复压进记忆」。
3. **确定性哈希嵌入 + 三道注入闸门**——给 DSL 补上语义近邻检索，且不需要任何模型（正好绕过「DeepSeek 没有 embeddings 接口」这个死结）。

**不值得搬的：** 记忆矩阵的 base64 内化存储、13 个新工具、双核软联动。

## 二、dsh-neural-memory 怎么做的

### 2.1 嵌入：确定性哈希，不是模型

三档 n-gram，权重 `ngram=[0.5,1.0,1.0]`、`hybrid=[0.45,1.0,1.0]`，每个 gram 投影两次：

```js
h = mix32(fnv1a(gram, salt + p * 0x27d4eb2d))
idx = h % dim ; sign = (h >>> 31) ? -1 : 1 ; out[idx] += sign * w
```

`K_SALT=0x9e3779b1`、`V_SALT=0x85ebca6b`，`scale=1/√2`，最后 L2 归一化。`dim` 默认 64，bundle 配 128。
（`nm/lib/model.js:78-109, 175-182, 222-237`）

虚词整串全命中时权重 ×0.4；hybrid 模式另加词级特征：英文停用词 `0.35*scale`、标识符 `1.85*scale`、普通词 `1.25*scale`，同特征取最大权重再乘 `1+ln(tf)`。（`lib/model.js:121-144, 271-287`）

**关键点**：纯函数、同文本必得同向量、零延迟、零依赖、可离线。这正是 DSL 缺的那块——`context.mjs:4` 里自己写着「DeepSeek 没有 embeddings 接口（v1/embeddings 返回 404），所以检索默认走本地词面索引」。

### 2.2 写入：靠「惊讶度」决定记不记

```js
pred = M · k ;  surprise = ‖pred − v‖²          // 预测误差
wrote  = surprise > 0.35 && (!alreadyKnown || surpriseRel > 0.02)
grad   = err ⊗ k ;  S ← βS − 2η·grad ;  M ← M + S
```

`η=0.2`、`momentum β` 默认 0、bundle 配 0.25。（`lib/model.js:1167-1242`）

意思是：**跟已有记忆不相似的东西才值得写**，相似的只更新 `strength` 和 `writes`。新条目 `strength=surprise`；命中写入时 `strength += surprise`。（`lib/model.js:1253-1270`）

记忆里有 `strength`（强度）、`writes`（被记住几次）、`createdAt`、`lastSeen`、`surprise`，容量上限 512 条，按 `strength` 降序切尾。（`lib/model.js:1308-1314`）

### 2.3 衰减与强化

- 衰减：`M *= (1-decay)`、`S *= (1-decay)`、每条 `strength *= (1-decay)`，`strength < 0.05` 直接剔除。日常 `decay=0.02`，自动遗忘另用 `0.015`。（`lib/model.js:1474-1485, 428-430`）
- 强化：召回**过闸之后**才 `strength = min(10, strength + 0.15)`、`lastSeen = now`。（`lib/model.js:1414-1427`）

这就是「常用记忆抗悬崖」的机制——DSL 只有单向半衰期，没有命中强化。

### 2.4 召回：三个量 + 三道闸

```js
readout  = M · k_q
score    = cos(readout, v_e)
coverage = |q_bigrams ∩ e_bigrams| / |q_bigrams|
margin   = top1 − top2
```

排序后过滤 `score >= 0.45 && coverage >= 0.25`；条目少（<10）时把分闸放开。（`lib/model.js:1359-1410`）

生命周期层再加一道：`entries>=4 && top1Score<0.72 && margin<0.08` → **不注入**。（`lib/lifecycle.js:296`）
冷却：同一记忆注入后 5 轮内不再注；检测到压缩序号上升就清冷却。（`lib/lifecycle.js:275-313`）

注入文本：首行 `【神经记忆 · 自动联想 · 非用户输入】`，每条 `- ${text} (r=${score})`，总上限 600 字，一条不成则截断加 `…`。（`lib/lifecycle.js:18-19, 152-181`）

### 2.5 观察：什么才算一条记忆

先删代码块与 ≥40 字符的行内码，再按 `[。！？；\n]+` 切句，保留 **12–220 字符**、剔寒暄/机器前缀/纯 URL/重复，一轮最多 4 句，观察阈值单列为 0.55。（`lib/lifecycle.js:75-95, 238-260`）

## 三、dsh-mind 怎么做的

### 3.1 压缩 prompt：从「写摘要」改成「给自己留交接便条」

它没改触发与区间（继承 `BasicCompactionEngine`），只改了 `summarize()` 的提示词。（`mind/lib/compaction.js:375-383`）

核心差异有四条，都是 DSL 现在没有的：

**① 身份**：「你就是上面这段对话里的那个助手本人……这不是给第三方写摘要，是你自己给未来的自己留字条」，全程第一人称，禁止「助手/该模型」。（`compaction.js:429-444` 的指令原文）

**② 结构里专门有一节记「没做成什么」**：

```text
## 未完成与待验证（**这一节专记"没做成什么"**）
- **计划过但还没执行**的动作（哪怕只在心里想过）
- **试过但失败**的方向，连同失败的具体原因
- **尚未验证**的假设、猜对了但没确认的结论
```

**③ 证据分级**：写「已验证」必须能指出具体工具输出或文件行号；记不清写「⚠️ 记不清，需重查」；推断写「⚠️ 推断，未验证」。三者不许混写。

**④ 授予怀疑权**：便条开头强制写上「这是我自己写的、有损的……如果眼前证据和它冲突，一律以眼前证据为准」。理由写得很直白：「模型会过度依赖上一轮总结而卡在错误路径上」。

另外还有「⛔ 不许写进便条的四类东西」：推测不升级为事实、不替未来下价值判断、不代许诺、不编没有输入的待办。

### 3.2 存档与区域展开

文件名 `${safeName(sessionId)}__${startSeq}-${endSeq}.json`，记录 `{sessionId,startSeq,endSeq,entries,bytes,truncated,items:[{seq,type,time,text}]}`。（`mind/lib/archive.js:78-80, 212-222`）

`expandRegion({sessionId, seq|fromSeq,toSeq, maxChars=60000})`：按文件名区间剪枝 → 取 `items` 里 `seq∈[lo,hi]` → 每条渲染 `── seq N [type] ──\n正文`。（`archive.js:281-352`）

`searchArchives` 是 **AND 子串**匹配，不是向量：空格切词、小写、`score = 1+log(tf)`（tf 上限 16），多词短语 +2.0。（`archive.js:387-473`）

摘要末尾自动附最近 8 个区间的索引 `- seq a..b（N KB，原文已存档）`。（`archive.js:476-493`）

### 3.3 lifeline：挑原话

只从「自己的段落」抽 `「…」` 里 4–60 字的引语，Set 去重，剔掉模板句（「上次是这样」「主人心情不好」「未结线索」），每篇 ≤3 条；路径 ≥6 字符且排除 `AGENTS.md`，≤4 条；按原文出现顺序，不排序。1300 字预算**从最近月份往前累加**，超限就丢远的。（`mind/lib/lifeline.js:107-129, 181-189, 577-598`）

### 3.4 工具账本（这条思路独立于记忆）

字段 `{at, tool, callId, outcome:'pending'|'ok'|'failed', chars, summary}`；缓存键 `${mtimeMs}:${size}`；写盘 1200ms 防抖 + `unref()` + 紧凑 JSON（约省 40%）。用途：压缩后第一步注入「最近的工具调用记录（原文可能已被压缩遮蔽）」，900 字上限。（`mind/lib/tool-ledger.js:55-118, 270-281, 389-439`）

### 3.5 注入总预算

`budget.total=6700`，分段配额 `psyche 1200 / tacit 1200 / diary 2000 / lifeline 1300 / ledger 900`；超了按 `lifeline→psyche→diary→ledger→tacit` 顺序削，总上限时削最长那段（lifeline 除外）。（`mind/lib/config.js:77-82`、`budget.js:44-82`）
节流按注入字数分档：`<2000` 字 10 分钟、`<6000` 20 分钟、否则 30 分钟。（`budget.js:132-139`）

## 四、DSL 现在是什么样

| 能力 | DSL 现状 | 位置 |
|---|---|---|
| 检索 | BM25 词面（汉字二元组 + 英文词） | `context.mjs:83-92, 207-226` |
| 稠密向量 | 仅归档片段可选存 ollama 向量，模型不在就退回 BM25 | `context.mjs:6-7` |
| 召回阈值 | 只有 `minScore`（默认 0.08），无 margin、无冷却、无「未命中就不注」纪律 | `context.mjs:236-253` |
| 时间衰减 | 单向半衰期 `0.5**(age/hl)`，命中不强化 | `context.mjs:231-234` |
| 压缩 | 一级段摘要（占用每涨 33%）+ 二级按时间权重合并（涨到 50%） | `server.mjs:3434, 3575, 3772-3808` |
| 压缩 prompt | 第三人称工具腔，四节（事实/决定/偏好/未完成） | `context.mjs:258-271` |
| 归档 | 按 `${from}-${to}.json` 落盘 + `index.json` 建 chunk 索引 | `server.mjs:3284-3310` |
| 归档回取 | **没有按区间取原文的接口**（只有压缩时读一次原文） | — |
| 跨会话检索 | `searchConversations` 逐会话全文 `indexOf`，44MB 全读 | `server.mjs:5215` |
| 用户画像 | `user-learn.mjs` 只有统计口径，没有原话引语 | `user-learn.mjs` |

## 五、六条可搬，逐条给落点

### ① 压缩便条 prompt 重写（最高优先级）

**搬什么**：`mind/lib/compaction.js` 里那套「第一人称交接便条 + 未完成/待验证专节 + 证据分级 + 怀疑权前言」。

**落在哪**：`deepseek-app/context.mjs:258` 的 `MEMORY_SYSTEM`（一级）与 `:283` 的 `CONSOLIDATE_SYSTEM`（二级）；`server.mjs:3466-3503` 的调用路径不用动。

**改动量**：改两个字符串常量，约 60 行文本。**零风险**，随时可回滚（`git checkout context.mjs`）。

**预期收益**：这是 DSL 压缩质量的天花板所在。现在的四节结构会丢掉「试过但失败」「推翻了什么」——而 DSL 的会话本身是长任务（改代码、调 QQ、查数据），这类信息恰恰最值钱。二级合并里已有「关键词索引」的思路，可以并进便条结构。

**注意**：DSL 的压缩正文是塞进 `conv.memory.text` 再拼进 system 的，第一人称不影响使用；但别把「女仆/主人」那套称呼搬过来——DSL 是桌面聊天应用，用户可能不是同一个关系。

### ② 惊讶度写入闸门

**搬什么**：写记忆之前先算「跟已有记忆有多不像」，不够不像就不写，只把 `strength` 加一点。

**落在哪**：`server.mjs:3434` `compactMemory()` 写 `conv.memory.records` 之前、`server.mjs:3575` `consolidateMemory()` 合并之前。DSL 的 `records` 已经是「分段 + 关键词 + gist」，正好可以当条目算相似度。

**最小实现**：用 ①的嵌入（见下条）给每条 record 算向量，新段跟现有段做余弦；`<0.35` 就合并进最相似那条（追加 `writes`）而不是新开一条。

**改动量**：约 40 行；风险低，只影响 `records` 数组的堆积速度。

### ③ 确定性哈希嵌入 + 三闸门召回

**搬什么**：`fnv1a + mix32 + 双投影 + L2` 这套（见 2.1），加 `score/coverage/margin` 三道闸与冷却。

**落在哪**：
- `context.mjs` 新增 `embedHash(text, dim=512, salt)`（照抄公式，`DIMS` 已有 512）；
- `chunkMessages()`（`context.mjs:114`）建索引时顺手给每个 chunk 存一份稠密向量；
- `retrieve()`（`context.mjs:236`）加 `minCoverage`、`minMargin`、`cooldownTurns`；
- `searchConversations()`（`server.mjs:5215`）**换成向量召回**：启动时给所有会话的 chunk 建一次向量表，落盘缓存到 `data/.vector-index.json`，查询时只算 query 向量再暴力点积（几千条 chunk 足够快），彻底干掉「每次搜索读 44MB」。

**改动量**：约 150 行；中等风险，建议先只用于 `/api/search`（新路径、有旧实现可对照），稳定后再接到 `buildMessages` 的 RAG。

**为什么不用 ollama**：DSL 已经试过「模型不在就退回 BM25」这条路，等于默认不可用。哈希嵌入没有这种降级分支，且不吃首字延迟——这点和刚做完的性能优化相容。

### ④ 强度 + 命中强化 + 容量淘汰

**搬什么**：`strength / writes / lastSeen`，衰减用 `ctxHalfLifeDays`，命中后 `+0.15` 上限 10，`strength<0.05` 淘汰。

**落在哪**：`context.mjs:231` `decayWeight()` 改成读 chunk 自己的 `strength`（没命中过的按原半衰期算），`retrieve()` 返回时更新 `lastSeen`/`strength`。

**改动量**：约 50 行，需要给 chunk 加字段 → 归档索引结构要升版本（`index.json` 加 `version`）。

### ⑤ 归档区域回取

**搬什么**：`expandRegion({from, to})` 这类「按条号区间把原文取回来」的接口，加进摘要末尾的区间索引。

**落在哪**：`server.mjs:3256` `archiveDirOf()` 附近加 `readArchiveRange(convId, from, to)`；`conv.memory.records[i].from/to` 已经有精确范围（`context.mjs:301` 就在用），直接暴露成 `GET /api/conversations/<id>/archive?from=&to=`，前端点记录能展开原文。

**改动量**：约 60 行（含前端一个小按钮）。这条能让「渐进激活」闭环——现在 `ctxProgressive` 只有关键词卡，没有真正的展开动作。

### ⑥ lifeline 式原话引语（给 user-learn 用）

**搬什么**：从用户自己说过的话里挑 3–5 条**原话**（4–60 字、去重、剔模板），作为语感范例注入，而不是只给统计数字。

**落在哪**：`user-learn.mjs` 的 `summaryOf()` / `buildOwnProfileText()` 后面加 `quotesOf()`；注入时追加「他最近这么说：」三行原文。

**改动量**：约 40 行。注意隐私：这些原话已经在本地库里，只是回灌给同一个模型，不新增外泄面。

## 六、不建议搬的

- **矩阵内化 + base64 持久化**（`M`/`S` 两个 `dim²` Float64 blob）：不可读、不可手改、不可 diff，出问题只能整份丢。DSL 的记忆要能被人看见、能改（用户会去看「记了什么」），纯 JSON 条目才合适。
- **13 个新工具**（6 + 7）：每个都进 prompt，对你现在这种「工具已经很多」的场景是净负担。真要用，用 `/api/*` 暴露、前端点，不进模型。
- **双核软联动**（`namespace: "mind"` 互相同步）：两个系统互相写对方的库，出问题无法归因。
- **mind 的 6700 字总预算 + 三段节流**：DSL 的上下文预算只有 24000 token（`CTX_DEFAULTS.ctxBudget`），6700 字注入会吃掉一大块。要搬就按比例砍到 800–1500 字。

## 七、如果只做三件事

1. **重写 `MEMORY_SYSTEM` / `CONSOLIDATE_SYSTEM`**（半天，零风险，收益最大）——先加「未完成与待验证」「已作废的结论」两节 + 证据分级三档。
2. **给 `/api/search` 换哈希向量召回**（一天，新路径，可对照旧实现）——顺手干掉 44MB 全读。
3. **惊讶度去重**（半天）——让 `conv.memory.records` 不再堆重复段。

④⑤⑥ 可以排在后面，都是「有了更好」而不是「缺了不行」。

## 附：核对过的技术事实

- 两包 tgz SHA256 与 release 一致：`2403FFA1…0154`（neural-memory）、`EC32EA1B…729F`（mind）。
- 全量扫描 `fetch(` / `http(s)://` / `child_process` / `execSync` / `spawn(`：两包**零命中**。
- neural-memory 数据落 `~/.dsh/state/dsh-neural-memory/<ns>.json`；mind 落 `~/.dsh/mind/`（`archives/`、`state.json`）。
- mind 的 `engines` 要求 `dsh>=0.2.1-rc.1`、`node>=22`。
- 两包都**没带 tests/ 目录**，发布方声称的 12/12、808/808 无法复跑。
